# همراه کوچک — ESP32-S3 مستقل

پروژه برای **Waveshare ESP32-S3-LCD-1.47 بدون B**، تراشه ESP32-S3R8، فلش 16MB و PSRAM هشت مگابایتی. مدل B پایهٔ نور متفاوت دارد و این فریمور برای آن نیست.

## این نسخه چه کاری انجام می‌دهد؟

- ۱۲ فرمان کوتاه فارسی با آموزش شخصی، سه نمونه برای هر فرمان؛ استخراج MFCC و تشخیص DTW **روی خود برد**.
- پاسخ‌های فارسی از پیش تولیدشده، داخل فلش برد؛ بدون API، اینترنت، مدل زبان یا سرویس گفتار ابری در زمان استفاده.
- نمونه‌های آموزشی در SPIFFS ذخیره می‌شوند و پس از ری‌استارت باقی می‌مانند. فایل صوتی خام آموزش ذخیره نمی‌شود؛ ویژگی‌های صوتی ذخیره می‌شوند.
- مرورگر میکروفون و اسپیکر دستگاه را برای تست تأمین می‌کند و ۱۲ چهرهٔ فیروزه‌ای، پلک‌زدن و حرکت دهان را نشان می‌دهد.
- LCD شکسته با GPIO48=LOW خاموش است و کنترلر ST7789 با GPIO39=LOW در reset نگه داشته می‌شود. هیچ تصویر یا راه‌اندازی LCD انجام نمی‌شود.

این نسخه **مکالمهٔ آزاد، تبدیل گفتار عمومی فارسی به متن یا تشخیص احساس از صدا نیست**. عبارت‌های آموزش‌دیده را با الگوی صوتی گوینده مقایسه می‌کند. حالت چهره بر اساس فرمان/وضعیت تغییر می‌کند. آستانهٔ تشخیص اولیه تجربی است و دقت واقعی باید با صدای شما، میکروفون و محیط واقعی ارزیابی شود. تا قبل از آموزش شخصی، دکمهٔ شنیدن پاسخ فقط پاسخ آماده را تست می‌کند.

## شروع صفحهٔ تست

در PowerShell از پوشهٔ پروژه:

```powershell
.\start.ps1
```

سپس [صفحهٔ محلی](http://127.0.0.1:8765) را در Chrome یا Edge باز کنید. سرور تنها روی loopback گوش می‌دهد.

۱. برد USB را وصل کنید و «اتصال» را بزنید.
۲. برای دو فرمان متفاوت، «آموزش با صدای من» را هرکدام حداقل دو بار بزنید؛ سه بار توصیه می‌شود.
۳. پس از اجازهٔ میکروفون، بلافاصله عبارت را یک بار بگویید. هر ضبط ۲٫۵ ثانیه است.
۴. «شروع صحبت» را بزنید و یک فرمان آموزش‌دیده را بگویید.
۵. «شنیدن پاسخ» صدای ذخیره‌شده را از **حافظهٔ خود برد** دریافت و پخش می‌کند؛ حتی بدون میکروفون قابل تست است.

صفحه و پل USB روی کامپیوتر اجرا می‌شوند، اما کامپیوتر تشخیص گفتار یا انتخاب پاسخ انجام نمی‌دهد. صدای میکروفون به PCM16 تک‌کاناله 16kHz تبدیل و از طریق USB به برد ارسال می‌شود. برد نتیجه، حالت چهره و WAV پاسخ را برمی‌گرداند. از Web Speech Recognition یا سرویس ابری استفاده نشده است. فایل‌های پروژه و صداها پس از نصب، بدون اینترنت کار می‌کنند.

**مرورگر روی گوشی:** آدرس HTTP کامپیوتر در شبکه اجازهٔ میکروفون ندارد و این سرور نیز به شبکهٔ عمومی bind نشده است. نسخهٔ فعلی پل USB برای دستگاه میزبان است؛ استفاده با گوشی نیاز به پل USB سازگار یا مسیر HTTPS دارد و در این نسخه پیاده نشده است. Python روی ESP32 نصب نمی‌شود.

## کار مستقل پس از اضافه‌کردن صدا

مسیر I2S داخل فریمور موجود است ولی چون قطعه‌ای وصل نیست، پیش‌فرض **غیرفعال** است. این مسیر بدون قطعات واقعی تست نشده است.

| قطعه | سیگنال | GPIO برد |
|---|---|---|
| INMP441 | SCK/BCLK | 4 |
| INMP441 | WS/LRCL | 5 |
| INMP441 | SD | 6 |
| INMP441 | VDD / GND / L-R | 3V3 / GND / GND (چپ) |
| MAX98357A | BCLK | 7 |
| MAX98357A | LRC | 8 |
| MAX98357A | DIN | 9 |
| MAX98357A | VIN / GND | 5V / GND مشترک |
| اسپیکر مناسب ماژول | خروجی آمپلی‌فایر | SPK+ و SPK-، هیچ‌کدام به GND وصل نشود |

پس از سیم‌کشی، ابتدا در صفحه «قطع اتصال» بزنید و اجرا کنید:

```powershell
.\.venv\Scripts\python.exe tools\boardctl.py --hardware on
```

فعال‌بودن سخت‌افزار در NVS ذخیره می‌شود. برد با منبع برق USB مستقل کار می‌کند؛ برای ضبط ۲٫۵ ثانیه‌ای دکمهٔ BOOT را یک بار فشار دهید. هنگام روشن‌کردن یا reset آن را نگه ندارید، چون وارد bootloader می‌شود. مسیر فعلی push-to-talk است و wake word ندارد. به‌دلیل تفاوت میکروفون‌ها، آموزش با میکروفون مرورگر ممکن است برای INMP441 نیاز به آموزش/تنظیم مجدد داشته باشد. رابط آموزش مستقیم I2S هنوز در صفحه وجود ندارد؛ استفادهٔ مستقل بعد از نصب قطعات نیاز به ارزیابی واقعی دارد.

برای غیرفعال‌کردن:

```powershell
.\.venv\Scripts\python.exe tools\boardctl.py --hardware off
```

آستانهٔ موقت (کوچک‌تر یعنی سخت‌گیرتر) با `--threshold 1.6` تنظیم می‌شود و پس از reboot به مقدار پیش‌فرض برمی‌گردد. این مقدار معیار آماری confidence نیست.

## نصب از ابتدا و ساخت

Python 3.12، Arduino IDE/CLI و پکیج `esp32` لازم است. ابزار موجود در این کامپیوتر Arduino ESP32 **3.3.10** است. نصب اولیه برای دانلود بسته‌ها و مدل تولید صدای فارسی اینترنت می‌خواهد:

```powershell
.\setup.ps1
.\flash.ps1 -Port COM3
```

اسکریپت provisioning مدل Piper فارسی amir را فقط برای تولید پاسخ‌های ثابت دانلود می‌کند. فایل‌های تولیدی `firmware/companion/replies.h`، `commands.h` و `web/audio/*.wav` هستند. تغییر پاسخ‌ها در `commands.json` به اجرای دوبارهٔ provisioning و فلش نیاز دارد. مدل تولید صدا در runtime استفاده نمی‌شود.

برد: `esp32:esp32:esp32s3`، Hardware CDC/JTAG، CDCOnBoot enabled، FlashSize=16M، PSRAM=opi. جدول پارتیشن اختصاصی: برنامه 7MiB و SPIFFS حدود 8.9MiB، بدون OTA در این نسخه. فلش‌کردن جدول پارتیشن متفاوت می‌تواند داده‌های برنامهٔ قبلی را جابه‌جا کند؛ قبل از اولین فلش از firmware قبلی نسخهٔ پشتیبان بگیرید. دستور `FORMAT TRAINING` فقط پس از provisioning اولیه و حفظ backup برای آماده‌کردن SPIFFS استفاده شود؛ نمونه‌های آموزش را پاک می‌کند.

ابزار `tools/backup.py` برای پشتیبان‌گیری chunked آزمایشی است. موفقیت را فقط زمانی تأیید می‌کند که `backups/original-flash.bin` با اندازهٔ دقیق 16,777,216 بایت و SHA256 ساخته شود. فایل‌های جزئی backup کامل نیستند. بازگردانی فقط با فایل کامل معتبر:

```powershell
python -m esptool --chip esp32s3 --port COM3 write-flash 0 backups\original-flash.bin
```

## ساختار و محدودیت تست

`firmware/companion/recognizer.h`: DSP مستقل از UI؛ `companion.ino`: USB، ذخیرهٔ آموزش، LCD-off و مسیر اختیاری I2S. `server.py`: پل شفاف USB با قفل تراکنش و دریافت طول‌دار WAV. `web/`: UI فارسی RTL و هندسهٔ پیکسلی بازطراحی‌شده از دو تصویر مرجع. `web/face.js` مبنای چهرهٔ نمایشگر بعدی است؛ هنوز درایور رندر روی نمایشگر جایگزین پیاده نشده، چون مدل آن مشخص نیست.

پروتکل: `STATUS`، `FACE name`، `SAY id`، `AUDIO train id bytes`، `AUDIO recognize -1 bytes`. برای AUDIO برد ابتدا JSON حاوی `ready:true` می‌فرستد، سپس تعداد مشخصی بایت PCM دریافت می‌کند. پاسخ صوتی یک خط JSON شامل `audio_bytes` دارد و بلافاصله همان تعداد بایت WAV می‌آید. نمونهٔ silence/خیلی‌کوتاه رد می‌شود؛ فرمان نامشخص پاسخ آمادهٔ «نشناختم» می‌گیرد.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

این تست‌ها framing و خطاهای USB bridge را بررسی می‌کنند؛ جای تست انسانی میکروفون یا صحت تشخیص فرمان روی برد را نمی‌گیرند. نتیجهٔ تست‌های واقعی در `VALIDATION.md` ثبت می‌شود.
